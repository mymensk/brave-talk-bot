# Интонация — руководство для разработчиков

Контекст проекта, архитектурные решения и правила разработки.

---

## 1. Что это за проект

**Интонация** (`@intonaciya_bot`) — ИИ-ассистент для разговоров с высокой ценой ошибки в текстовой переписке. Проект участвует в акселераторе **Sber500 x DISRUPT**.

Приоритет — быстрая выкатка работающего продукта живым пользователям. Не строй абстракции «на вырост» там, где это тормозит релиз.

Репозиторий: `https://github.com/mymensk/intonaciya-bot`

---

## 2. Продукт

### Боль

Когда цена ошибки в переписке высока (знакомство, флирт, извинение, отказ, сложное сообщение руководителю), человек знает, что хочет сказать, но не находит форму. Итог — шаблонное «Привет, как дела?» или молчание.

### Позиционирование: коуч, а не гострайтер

Это принципиальное решение, влияющее на промпты и UX.

| Не делаем | Делаем |
|---|---|
| «Напиши за меня» | «Разблокируй меня» |
| Бот отдаёт готовый текст под отправку | Бот даёт 3 направления + объяснение эффекта |
| Пользователь копирует и шлёт | Пользователь пишет сам |

Причина: продукт, пишущий за пользователя, порождает страх разоблачения и ощущение обмана у собеседника. Поэтому **каждый вариант ответа всегда сопровождается пояснением, какой эффект он произведёт**.

### Сценарии

1. **Первое сообщение** — открывашка по анкете/первому сообщению собеседника
2. **Возврат в затухший диалог** — как написать после паузы без неловкости
3. **Дешифровка** — «что она имела в виду этим сообщением»
4. **Регулятор тона** — пользователь даёт свой черновик, бот даёт версии: мягче / смелее / смешнее / короче
5. **Тяжёлые разговоры** — извинение, отказ, границы, сообщение руководителю
6. **Тренажёр** — бот отыгрывает собеседника по его стилю, пользователь репетирует
7. **Защитный слой** — подсветка манипуляций и признаков романтического мошенничества

### Механики шеринга

- Карточка «Разбор переписки» с водяным знаком для форварда
- Реферальный анлок бесплатных разборов
- Групповой режим: бот в общем чате друзей

## 3. Архитектура и стек

### Форм-фактор

**MVP — Telegram-бот и Mini App, не мобильное приложение.**

- Настоящая клавиатура на iOS **не видит сообщения собеседника** — sandbox даёт расширению только то, что пользователь сам набирает. Без контекста диалога ценность подсказки нулевая.
- На Android чтение контекста экрана через `AccessibilityService` нарушает политику Google Play.
- Telegram: ноль трения при установке, обновления без модерации сторов, встроенный шеринг, платежи.

Позже: мобильное приложение + keyboard extension в режиме «регулятор тона» (сценарий 4) — он не требует доступа к чужим сообщениям и реализуем в рамках ограничений iOS.

### Стек

```
Backend:       Python 3.12, aiogram 3, FastAPI (Mini App + вебхуки), asyncio
LLM:           GigaChat API
Распознавание: vision-режим GigaChat либо Yandex Vision OCR
БД:            PostgreSQL
Кэш/очереди:   Redis
Инфра:         VPS в РФ, Docker, GitHub Actions
Аналитика:     события в PostgreSQL + Metabase
Мониторинг:    Sentry + структурные логи
Платежи:       Telegram Stars → ЮKassa
Карточки:      Pillow
```

### Ввод диалога — две итерации

**Итерация 1: форвард сообщений в бота.** Telegram передаёт авторство каждой реплики в метаданных. Распознавание не нужно, точность стопроцентная.

**Итерация 2: скриншот.** Ловушка: **плоский OCR теряет авторство сообщений.** В скриншоте принадлежность реплики кодируется положением пузыря — слева собеседник, справа пользователь. Решения, в порядке предпочтения:
1. Vision-модель напрямую (понимает и текст, и вёрстку)
2. OCR с bounding boxes + эвристика: делим ширину скриншота пополам, атрибутируем реплики по горизонтальной позиции блока

### Абстракция над LLM

Провайдер модели выносится за интерфейс `LLMProvider` с методом генерации и методом модерации.

## 4. Приватность и модерация — архитектурные требования

Продукт работает с личной перепиской, включая данные второго человека, который согласия не давал.

**Жёсткие правила, нарушать нельзя:**

1. **Содержимое переписок не сохраняется.** Обработка in-memory, скриншоты удаляются сразу после формирования ответа. В БД — только события и метрики, без текстов.
2. **Не логировать тексты диалогов.** Ни в Sentry, ни в файловые логи, ни в отладочный вывод. Логируем идентификаторы, тайминги, коды ошибок.
3. **Возрастной гейт 18+** с фиксацией подтверждения. Модель обязана отказывать, если в контексте есть признаки несовершеннолетнего.
4. **Модерация на входе и выходе.** Отсекаем запросы на преследование, давление, обман. Не генерируем манипулятивный текст. Реализуется системными ограничениями промпта + отдельным проверочным вызовом.

## 5. Конвенции

**Язык.** Код и комментарии — английский. Тексты интерфейса, промпты и сообщения пользователю — русский. Документация в репозитории — русский.

**Промпты** живут в отдельных файлах (`prompts/`), не в коде. Их правят чаще всего, и правит не только разработчик.

**Код.** Асинхронный по умолчанию. Type hints обязательны. Форматирование ruff. Конфигурация через переменные окружения, `.env` в `.gitignore`, `.env.example` в репозитории.

**Секреты.** Токены GigaChat, Telegram и GitHub никогда не попадают в код, коммиты и логи.

**Тесты.** Покрываем логику атрибуции реплик, парсинг форвардов, лимиты и модерацию. Вызовы LLM в тестах мокаются.

**Коммиты.** Осмысленные сообщения на английском, conventional commits.

**Публичность.** Репозиторий публичный. Внутренние материалы (планы, метрики, риски, бизнес-заметки) в него не попадают.
